# V-UP! 推廣策略企劃（修正版）
> 狀態：🟡 市場驗證提案階段 | 更新：2026-05-03

---

## ⚠️ 重要前提確認

| 項目 | 現況 |
|------|------|
| 服務狀態 | **提案 / 市場驗證階段**，非正式上線服務 |
| 推廣目的 | 蒐集市場反饋，驗證「里程碑應援」概念是否被接受 |
| 開放範圍 | 首頁介紹 + 試玩版體驗（不開放真實交易、不開放真實帳號） |
| 製作量原則 | **YAGNI**：只做最小可驗證的東西 |

## 一、目標受眾（雙軸，創作者略優先）

```
優先順序：VTuber 創作者（P1） > 粉絲（P2）

原因：
- 創作者是平台存活的根本（沒有 VTuber 就沒有粉絲）
- 提案階段，一位創作者願意試用 = 比 100 個粉絲更有說服力
- 粉絲的驗證問題是「會不會願意贊助里程碑」，可以透過試玩間接驗證
```

---

## 二、首頁（Landing Page）最小範圍修正

> 原則：**改文案為主，不動現有 CSS / 動畫**

### 必做（P0）— 只改文字，不加新區塊

**Hero 文案改版**（粉絲 + 創作者雙訴求，創作者 CTA 提升）：

```
Pill（小標）：「✨ 概念提案中 — 歡迎體驗並給我們意見」

H1：「讓每一份應援，都成為 VTuber 的里程碑」

副標（雙視角）：
  粉絲：看著她的夢想一步一步實現
  創作者：讓粉絲的支持，化成真正完成的企劃

CTA 順序調整（創作者優先）：
  [🌟 我是 VTuber，想了解這個平台]   [💜 我是粉絲，我要體驗試玩]
```

**How It Works 步驟修正**（改為雙視角各 3 步）：

- 現況：Step 1 說「VTuber 後台發起」對粉絲毫無意義
- 修正：拆成「創作者篇」與「粉絲篇」各一組 how-step，切換顯示
- 或更簡單：只保留粉絲篇（創作者靠 CTA 導流至 Dashboard Demo）

### 不做（節省製作量）

- ❌ Social Proof 數字帶（提案階段數字沒說服力）
- ❌ 創作者獨立 Section（Hero CTA 已覆蓋）
- ❌ 成功案例 / 用戶心聲（尚無真實資料）
- ❌ 影片或動畫素材製作

## 三、試玩版（Demo Flow）精簡設計

> 目標：讓訪客在 **不需要帳號、不需要信用卡** 的情況下，感受核心 UX

### 最小可行 Demo（只需改現有頁面）

**已有的基礎**（`V-UP_Requirements.md` Phase 2 已規劃）：
- `vtuber_profile.html?id=demo` — 靜態 seed data，無需 Firebase
- Demo Banner 提示條（已在規劃中）

**需要新增的部分（最小）**：

```
① Landing Page Hero 加一個 Demo 入口按鈕
   → [👀 試玩看看（無需帳號）] → 導向 vtuber_profile.html?id=demo

② Demo 頁頂部試玩工具列（一行文字 + 按鈕）
   「🎮 試玩模式 | 500 V點可用 | [試著贊助看看]  [這是什麼？]」

③ Payment Modal 沙盒化
   - 新增一個判斷：if (isDemoMode) → 隱藏信用卡欄位，只顯示「使用 V點」
   - 確認後：localStorage 模擬扣點，進度條更新（本地端，不寫 Firebase）

④ 完成後顯示一則 Toast / Modal
   「✨ 恭喜！你剛體驗了 V-UP 的應援流程！
    [留下意見回饋] 或 [繼續試玩]」
```

**創作者 Demo 路徑（極簡）**：
- 直接導向現有 `dashboard.html`（已有 Demo 資料）
- 頂部加 Demo Banner 說明「此為提案展示，資料不會真實儲存」
- 不需要額外開發，只需要開 Banner

## 四、反饋蒐集機制（輕量）

> 提案階段最重要的產出：蒐集到「創作者 / 粉絲是否覺得這個概念有價值」

**最簡單方案**：在 Demo 完成 Toast 加一個 Google Form 連結

```
Toast 內容：
「你覺得這個平台有意義嗎？
 →  [填寫 2 分鐘意見表單（Google Form）]」
```

Google Form 問題（建議 3 題以內）：
1. 你是創作者還是粉絲？
2. 你認為里程碑應援的概念吸引你嗎？（1-5 分）
3. 你最期待這個平台的哪個功能？（開放填寫）

## 五、數據追蹤 (Google Tag Manager)

> 為了了解使用者的真實行為與轉化漏斗，需要引入 GTM (GTM-P97H54KD) 來捕捉關鍵數據。

**追蹤重點（Custom Events）**：
1. **Landing Page 點擊**：
   - `click_creator_cta`：首頁點擊「我是 VTuber 創作者」了解更多的次數。
   - `click_fan_demo`：首頁點擊「粉絲試玩體驗」的次數。
2. **Demo 漏斗**：
   - `start_demo_payment`：在試玩頁點擊「立刻支持」開啟付款 modal 的次數。
   - `finish_demo_payment`：完成模擬扣點並看到成功 Toast 的次數。
3. **回饋轉換**：
   - `click_feedback_form`：在 Toast 點擊前往 Google Form 的次數。

## 七、決策記錄

| 決策 | 選擇 | 理由 |
|------|------|------|
| Demo 機制 | 前端沙盒（localStorage） | 零 Firebase 依賴，製作量最小 |
| 首頁範圍 | 只改現有文案，不加新區塊 | 節省製作量 |
| 受眾優先 | 創作者 CTA 排第一 | 提案階段創作者驗證更關鍵 |
| 反饋蒐集 | Google Form（外部） | 不需要開發後台，最輕量 |
| 數據追蹤 | GTM Event Tracking | 驗證漏斗流失率與兩邊受眾的點擊佔比 |
