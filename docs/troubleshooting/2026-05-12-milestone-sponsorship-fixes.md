# V-UP 里程碑贊助系統 (Milestone Sponsorship) 故障排除與修正報告

## 背景概述 (Background)
本報告記錄了 2026 年 5 月 12 日在 `vtuber_profile.html` 里程碑贊助流程中，所遇到的一系列狀態無法更新、贊助行為中斷及 UI 錯誤問題。透過 Systematic Debugging 方法，我們排除了從前端 UI 狀態、服務層呼叫到後端 Firestore 規則的一連串錯誤。

## 問題與修正細節 (Issues & Fixes)

### 1. 達標時無法自動轉換狀態為 Achieved (Firestore 權限阻擋)
- **現象**：當粉絲贊助使里程碑 `currentAmount` 達到 `targetAmount` 時，系統嘗試自動將狀態更新為 `achieved`，卻拋出 `FirebaseError: Missing or insufficient permissions`，導致進度卡在 `published`。
- **根本原因**：`firestore.rules` 內的「粉絲贊助更新規則 (Fan sponsor update)」原先只允許更新 `['currentAmount', 'totalSupporters', 'updatedAt']`。當後端服務 (`payment.service.js`) 嘗試一併寫入 `status: 'achieved'` 時，因不在允許的欄位清單中而被阻擋。
- **解決方案**：
  - **Firestore Rules**：將粉絲贊助規則拆分為 2a (一般進度更新) 與 2b (達標更新)。在 2b 規則中，當 `currentAmount >= targetAmount` 時，明確允許寫入 `status` 與 `achievedAt`。
  - **Payment Service**：將 `status='achieved'` 的狀態翻轉邏輯，從獨立的 `updateDoc` 移動到原本的 Transaction 內部 (`t.update`)，確保資料一致性並滿足 Rule 2b 對 `affectedKeys` 的嚴格要求。

### 2. 前端 ReferenceError 導致贊助流程崩潰
- **現象**：用戶點擊贊助後，出現紅色錯誤訊息「贊助失敗: ReferenceError: result is not defined」，流程中斷。
- **根本原因**：在 `vtuber_profile.html` 的 `simulatePaymentAPI()` 函式中，由於變數作用域問題，未宣告 `result` 變數即直接賦值及讀取，導致 JavaScript 拋出 ReferenceError。
- **解決方案**：在 `try` 區塊最上方加入 `let result = null;` 宣告，正確承接 `PaymentService.initiate` 回傳的包含 `justAchieved` 屬性的物件。

### 3. 排行榜服務缺少依賴導致的 ReferenceError
- **現象**：控制台出現 `ReferenceError: getDoc is not defined` 錯誤。
- **根本原因**：`js/services/milestones.service.js` 檔案中實作 `listenRankings` (即時贊助排行榜抓取最新頭像) 時使用了 `getDoc`，但頂部 import 區塊遺漏了該函數。
- **解決方案**：在 `milestones.service.js` 頂部的 `firebase/firestore` import 列表補上 `getDoc`。

### 4. 首次贊助 (無 Profile 的用戶) 引發的 Firestore NOT_FOUND 錯誤
- **現象**：全新註冊的粉絲帳號點擊贊助時，沒有任何反應或出現「無法更新文件」的錯誤。
- **根本原因**：當新使用者還沒有在 `users` 集合中擁有對應的 Profile 文件時，`payment.service.js` 內部呼叫了 `t.update(userDocRef, userUpdates)` 以發放徽章。由於 `update` 要求文件必須存在，否則會直接觸發 Transaction 失敗。
- **解決方案**：將 `t.update(userDocRef, userUpdates)` 變更為 `t.set(userDocRef, userUpdates, { merge: true })`。如此一來，若文件不存在會安全地新建，存在則進行合併更新。

### 5. 前端 Auth 狀態未同步導致的假訪客權限錯誤
- **現象**：有時明明已登入，點擊贊助卻報錯 `initiateGuest error FirebaseError: Missing or insufficient permissions.`。
- **根本原因**：`vtuber_profile.html` 內的 `simulatePaymentAPI` 判斷登入狀態是依賴 `window.auth.currentUser`。若在頁面剛載入、Firebase Auth 尚未同步完成的瞬間點擊贊助，系統會誤判為「未登入訪客」，進而呼叫 `initiateGuest`。但 Firestore 後端卻能正確識別該請求帶有真實 Auth Token，導致「登入者嘗試發送未帶 fanUid 的訪客交易」這件事被 `transactions` 的安全規則阻擋。
- **解決方案**：在按鈕邏輯中引入雙重狀態驗證 (利用本地快取的 `window._pmCurrentUserData`)。若發現存在用戶資料快取但 Auth 物件尚未就緒，則暫停流程並提示「登入狀態同步中，請稍候幾秒再試」，避免進入錯誤的訪客分支。
